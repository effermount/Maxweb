# Разработка «Обла»

## Разработка и проверка

Нужны Mac с Intel или Apple Silicon, Node.js LTS и Command Line Tools. `npm run build` и `npm run dist` собирают обе архитектуры и объединяют их в `dist/mac-universal/Maxweb.app`. Electron загружается отдельно для каждой архитектуры; установленная локальная копия Electron не используется как общий бинарный шаблон.

```sh
npm ci
npm start
npm test
npm run test:runtime
npm run test:installer
npm run build
npm run dist
```

`./scripts/npm.sh` использует системный Node.js или локальный `.tools/node`; пример: `./scripts/npm.sh run dist`. `npm run icons` создаёт иконки и фон DMG из `scripts/icons.swift`. Проверки переименования: `node --test tests/brand.test.cjs tests/release-notes.test.cjs`, `electron tests/brand-runtime.cjs`, `node tests/brand-migration.cjs`. Проверка готовой сборки и имени в Finder: `node tests/brand-package.cjs`.

- Модульные тесты проверяют миграцию профиля 1.0, URL и разрешения, изоляцию идентификаторов аккаунтов, подписи выпусков, защиту от понижения версии и повреждённых загрузок.
- Проверка Electron запускает два временных аккаунта, проверяет cookies/localStorage, переключение без перезагрузки, маршрутизацию клика по уведомлению, счётчики, фоновый режим и восстановление после ошибки сети. Затем процесс полностью перезапускается и проверяется сохранение обеих сессий.
- Дополнительные проверки Electron на локальной странице MAX проверяют имя профиля, свёрнутую панель, оформление и маршрутизацию нативных уведомлений, код, защищённые IPC, скрытие представлений, отложенный клик, сон, бездействие и запуск заблокированным после настоящего перезапуска. Нативные баннеры в этих тестах заменены заглушкой; сообщения не отправляются.
- Проверка установщика создаёт две небольшие тестовые `.app`, подписывает архив отдельным временным ключом, выполняет настоящую замену после выхода процесса и проверяет запуск новой версии и сохранение файлов профиля. Основное приложение и пользовательский профиль не затрагиваются.

## Как выпускать обновления

При первоначальной подготовке выпуска создан ключ `.release/signing-private.pem`. **Сохраните его резервную копию.** Он исключён из Git и из приложения. В репозитории и клиенте находится только `assets/release-public.pem`. Для следующих выпусков нужен тот же приватный ключ: клиенты отвергают обновления, подписанные другим ключом. Не публикуйте папки `.release`, `.tools`, `node_modules` или пользовательские профили.

1. Укажите публичный GitHub-репозиторий в `src/release-config.json`.
2. Увеличьте версию в `package.json` и `package-lock.json`, обновите `RELEASE_NOTES.md`. В описание обновления попадёт только раздел соответствующей версии, без истории и повторного заголовка.
3. Выполните проверки, `npm run dist` и `npm run dist:win`. Создаются Universal Mac `.dmg` / `.zip`, Windows `.exe` / `.zip` и три подписанных описания обновлений.
4. Сохраните исходники в Git-коммите. `npm run publish:release -- --staged` публикует `main`, тег и предварительный выпуск с семью файлами; стабильный канал ещё не меняется. Нужны настроенный `origin` и авторизованный GitHub CLI.
5. Запустите `gh workflow run windows-update-test.yml -f release_tag=vX.Y.Z`. После успешной проверки настоящего NSIS на Windows переведите выпуск в стабильный: `gh release edit vX.Y.Z --prerelease=false --latest`.
6. Релиз содержит **latest-mac.json**, совместимый **latest.json**, Mac DMG и ZIP, **latest-windows.json**, Windows EXE и ZIP. Автообновление Mac использует ZIP; Windows — EXE, проверенный по подписи описания и SHA-256.

Для простой локальной сборки из публичных исходников приватный ключ не нужен (`npm run build`). Подготовка подписанного `latest.json` требует ключа владельца выпусков. Никакие приватные ключи, данные авторизаций MAX или учётные данные GitHub не входят в выпускаемые файлы.

## Telegram

При добавлении аккаунта выберите **MAX**, **Telegram**, **WhatsApp** или **VK Мессенджер**. Каждый аккаунт использует отдельное хранилище Electron; существующие сессии MAX сохраняются. Telegram открывает официальный Web K с его штатной авторизацией.

Поддерживаются имя и фото собственного профиля, локальное переименование, нативные уведомления с переходом в аккаунт, отключение баннеров отдельно для аккаунта, общий масштаб содержимого и общая блокировка кодом / Touch ID. Выход очищает локальную сессию выбранного аккаунта и удаляет его значок. Тип мессенджера виден в боковой панели, включая свёрнутый вид.

Для MAX читается запись `viewer` и при наличии более свежих данных — ровно одна запись `contacts` с ID собственного аккаунта. Telegram преобразует локальные blob-аватары через элемент изображения: CSP веб-клиента может запрещать `fetch(blob:)` даже для отображаемых аватаров.

Адаптер собственного профиля использует интерфейсы, проверенные по [исходникам Telegram Web K](https://github.com/morethanwords/tweb): `getSelf()` и загрузку своего аватара. Контакты, переписка и ключи авторизации не читаются. Если Telegram изменит эти интерфейсы, последнее имя и фото сохранятся; имя можно изменить вручную. Авторизацию реального пользователя и приход настоящего сообщения необходимо проверить после входа; автоматические проверки используют временные сессии и тестовые страницы.

При временной ошибке загрузки фото сохранённая аватарка остаётся. Telegram повторяет запрос, если загрузчик ещё не вернул адрес изображения; WhatsApp обновляет неполные записи своего фото в кэше. Для MAX, WhatsApp и VK при блокировке запроса изображения со стороны веб-страницы используется резервная загрузка через основной процесс: только HTTPS-серверы изображений соответствующего мессенджера, без cookies и с ограничением 2 МиБ. Адреса перенаправлений проверяются до запроса. Изображение преобразуется локально в миниатюру PNG; на сервер разработчика оно не отправляется. Проверка только этих сценариев: `electron tests/avatar-runtime.cjs` и `node --test tests/avatar.test.cjs`.

Прокрутка MAX после отправки учитывает плавающее поле ввода: последнее своё сообщение поднимается над ним. Ручная прокрутка отменяет автоматическое доведение; входящие сообщения сами по себе не вызывают скачка.


## WhatsApp

В выборе мессенджера доступен **WhatsApp**. Открывается официальный WhatsApp Web с привязкой устройства через его штатную страницу входа. Каждый аккаунт получает отдельный раздел `persist:whatsapp-…`; данные MAX и Telegram не перемещаются и не копируются.

Работают переключение аккаунтов, локальное переименование, масштаб содержимого, нативные уведомления с переходом в аккаунт, отключение баннеров отдельно для аккаунта, общая блокировка и выход с очисткой локальной сессии. Внутренние методы автоматического чтения имени и аватара ограничены собственным профилем; контакты, переписка и ключи авторизации не читаются. При недоступности данных сохраняются последние имя и фото, имя можно изменить вручную.

Адаптер имени использует собственное отображаемое имя WhatsApp, а фото — собственную миниатюру профиля; варианты интерфейсов сверены с [исходниками WA-JS](https://github.com/wppconnect-team/wa-js). Библиотека автоматизации в приложение не включается; работа с сообщениями остаётся в официальной веб-странице. Страница входа проверяется в чистой сессии Electron; настоящую привязку и получение сообщения следует проверить после входа пользователя.

В свёрнутой панели аватары увеличены до 44 px, инициалы находятся по центру. Кнопка уведомлений и значок мессенджера встроены в нижние углы. Активный профиль выделяется рамкой и индикатором без фоновой заливки; собственный цвет аватара сохраняется.


## VK Мессенджер

В выборе мессенджера доступен **VK Мессенджер**. Открывается [официальная веб-версия](https://web.vk.me/); на стартовой странице выберите «Общение ВКонтакте» и продолжите штатный вход через VK ID. Каждый аккаунт использует отдельный раздел `persist:vk-…`, включая cookies авторизации.

Переходы VK ID разрешены только для точных HTTPS-адресов `id.vk.ru`, `id.vk.com`, `login.vk.ru`, `login.vk.com`, `oauth.vk.ru`, `oauth.vk.com`. Эти страницы не получают доступ к IPC профилей и уведомлений. Окно входа использует сессию открывшего его аккаунта и закрывается при блокировке или выходе; ввод в нём учитывается таймером бездействия.

Поддерживаются переключение, локальное переименование, общий масштаб, нативные уведомления, отключение баннеров по аккаунту, общая блокировка и выход с очисткой локальной сессии. Имя и фото могут подтягиваться из модели кнопки меню VK с проверкой ID собственного аккаунта, из заголовка своего аккаунта в открытом меню или из явно обозначенного элемента своего профиля; если VK их там не показывает, остаются последнее сохранённое имя/фото и возможность переименования. Заголовки чатов, контакты, переписка и токены для получения профиля не читаются.

Проверки выполняются в временных сессиях с тестовыми страницами. Настоящий вход, получение сообщений и доступность своего профиля после входа требуют ручной проверки. При изменении внутренних интерфейсов веб-мессенджеров получение имени и аватара может потребовать адаптации.


Порядок аккаунтов можно менять перетаскиванием в свёрнутой и раскрытой панели. Также доступны **Alt+↑ / Alt+↓** на кнопке аккаунта. Порядок сохраняется после перезапуска; сочетания **⌘1–9** и циклическое переключение используют новый порядок. Перемещение не переключает активный аккаунт и не пересоздаёт его сессию.

В раскрытой панели длинное имя переносится на следующую строку, вместо обрезки многоточием. Значки мессенджера и уведомлений встроены в аватар, а кнопка редактирования находится справа напротив первой строки имени.

Для перемещения зажмите аватар или название аккаунта и тяните мышью: карточка следует за указателем, линия показывает место вставки. Отпустите кнопку мыши для сохранения. **Esc** или отпускание вне списка отменяет перенос.

## Скриншоты для README

```sh
npx electron scripts/screenshots.cjs
```

Скрипт снимает настоящий интерфейс в отдельном временном профиле с четырьмя демонстрационными аккаунтами. Веб-страницы мессенджеров заменены локальной пустой страницей; запрос Touch ID не вызывается. Личный профиль не используется. Готовые PNG сохраняются в `docs/screenshots/`; фирменные рамки и подписи создаются в HTML/CSS.
